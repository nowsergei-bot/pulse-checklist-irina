# Граница мастерской Ирины

## Действующий порядок владельца от 15 октября 2026

Рабочие ветки разделены:

- `irina/checklist` — существующие файлы чек-листа из `editable` в `isolation-manifest.json`, кроме SQL-миграций и общего `backend/functions/pulse-self-analysis-links.js`.
- `irina/english-monitoring` — только `modules/monitoring/`.
- В любой из двух веток разрешено создавать новые разделы в `modules/irina/<slug>/`. Их можно размещать в любых кабинетах через `module.json`, без правок чужих существующих разделов и общего меню.

Обязательные файлы нового раздела: `module.json`, `pages/index.tsx`, `server/index.cjs`. Пример манифеста: `{"id":"new-section","title":"Новый раздел","cabinets":["/cabinet/english","/cabinet/events"]}`. `id` совпадает с папкой; `cabinets: ["*"]` показывает ссылку во всех тестовых кабинетах. Разрешены подпапки `pages`, `server`, `assets`, `migrations`, а также `README.md` и `module.json`. Используй уже установленные зависимости. Сервер экспортирует async-функцию `{method,path,query,body,user,db,files,schema} => {status,body}`. Собственные таблицы — только в схеме `irina`, с явным указанием схемы в SQL; API — `/api/irina/<slug>/...`.

`context`, ядро, авторизация, CI, манифест изоляции, защитные скрипты, Docker, корневые package/lock-файлы и чужие разделы неизменяемы. Не добавляй symlink, submodule, секреты, рабочие ответы или выгрузки. Новые миграции добавляются последовательно внутри своего модуля; уже применённые не редактируются и не удаляются. Самостоятельный облачный деплой, миграции и сиды рабочей базы запрещены.

Получай свежую нужную ветку перед работой, сохраняй местные правки и совмещай конфликты. Веди отдельные ветки для задач чек-листа и мониторинга; не смешивай их. Force-push запрещён. Перед commit/push проверь diff, сборку, выбранные тесты и `python3 scripts/check_scope.py`.

PR и подтверждение Сергея для каждого тестового обновления не нужны. Доверенный процесс владельца проверяет границу, собирает полный код в закрытом GitHub и публикует только в изолированный контур Сергея и Ирины. Тестовая база отделена от рабочих данных. Публикация для остальных пользователей — отдельное действие владельца. Старую ветку `codex/checklist-irina` и старый запрос глобальной публикации не использовать для разработки/релиза.

На момент обновления файла установка нового контура ещё проверяется. До подтверждённого серверного релиза сообщай только «правки отправлены/проверены», а не «опубликованы». Ключи сервера, БД и закрытого GitHub Ирины не нужны. Этот раздел заменяет противоречащие ему старые инструкции в других файлах.
