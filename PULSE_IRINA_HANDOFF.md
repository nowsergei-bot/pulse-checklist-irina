# Новый Пульс: справочник существующих кабинетов для Ирины

Рабочий сайт: https://pulse.primakov-school.ru
Мастерская: https://github.com/nowsergei-bot/pulse-checklist-irina
Рабочая ветка: codex/checklist-irina. Аккаунт Irikossecure-hub имеет Write.
Тестовый сайт: https://monitoring-test.primakov-school.ru

## Цель и полномочия

Ирина самостоятельно меняет чек-листы и аналитику мониторинга английского. Ей необходимо находить существующие кабинеты, понимать маршруты, правила и связи. Создание новых кабинетов не является задачей. Обычные изменения в согласованных модулях не требуют повторного участия Сергея.

Кабинет — это маршрут приложения и права текущего пользователя, а не универсальная запись с cabinet_id. Не смешивать user_id, teacher_id, group_id, class_id и academic_year_id. Наличие ID и назначенной роли не даёт доступа к данным.

## Технический справочник

Новый серверный обработчик: GET /api/monitoring/directory/cabinets.
Только штатная сессия Пульса и роль data_admin модуля, перечитываемая сервером.
Параметры: user_id — точный ID, after — курсор, limit — от 1 до 100 (по умолчанию 50).

Ответ: ID пользователя, назначенные роли, явные связи преподаватель → группа → класс → учебный год, известные маршруты и пути исходников правил. Пагинация next_after. Только чтение. По отдельному поручению владельца возвращаются account_email учётной записи и teacher_email преподавателя. Имена, телефоны, ученики, ответы, оценки, файлы и сессии не возвращаются. Не сохранять реальные ID и ответы этого API в публичном коде, логах и задачах.

Поле effective_access=not_evaluated означает: справочник не вычисляет полные права чужого пользователя. Права определяет существующий обработчик раздела. Связи по ФИО/почте, временные назначения чек-листа и области кафедр этому API недоступны. При отсутствии явной связи не угадывать её и не считать кабинет отсутствующим. Для выбора конкретного человека использовать защищённый интерфейс Пульса; разработчику передавать выбранный ID.

Это новый API в исходниках мастерской. Он станет доступен в среде только после подтверждённой публикации. ID и связи читаются из БД этой среды; тестовые значения не считать автоматически рабочими.

## Где находятся правила

- frontend/src/app/routes.tsx — дерево существующих маршрутов.
- backend/functions/lib/pulse-access-v4.js — дополнительные назначения доступа.
- backend/functions/lib/visit-checklist-visibility.js — видимость чек-листов.
- backend/functions/lib/english-assessment-access.js — доступ английского, сопоставление преподавателя и группы.
- modules/monitoring/server/lib/access.cjs — права мониторинга.

Полные правила находятся в закрытом nowsergei-bot/survey-app. Их следует изучать через доступ на чтение либо проверенную копию без персональных данных. Доступ к полному закрытому репозиторию этой настройкой не выдан. Не копировать его целиком в публичную мастерскую: в исходниках могут встречаться персональные справочники и исторические данные.

## Разработка и публикация

Перед работой прочитать AGENTS.md и modules/monitoring/README.md, получить свежую ветку. Допустимы личные ветки staff/irina-kostyukovich/<task>; для публикации совместить проверенные правки с актуальной codex/checklist-irina. Не применять force-push.

Мониторинг: разрешены modules/monitoring/** и новые последовательные миграции в этой папке. Запись только monitoring, общие данные через pulse_read. Чек-лист: editable-пути isolation-manifest.json. Не расширять роль БД и не выдавать новые пользовательские права этим справочником.

Проверки: сборка frontend, тесты frontend и backend, scripts/check_scope.py; тест нового обработчика — node --test modules/monitoring/server/cabinet-directory.test.cjs.

Push интеграционной ветки запрашивает тестовую публикацию. Успех запроса не равен установленному релизу: после входа сверить /api/monitoring/version с SHA мастерской. Затем Ирина самостоятельно запускает Actions → Publish verified monitoring to working Pulse → Run workflow → codex/checklist-irina. Проверить установленную версию и нужное поведение.

Действующий рабочий издатель переносит modules/monitoring/**. Автономный перенос правок чек-листа в новый Пульс этим механизмом не подтверждён; не выдавать их push за публикацию. Расширение издателя, доступ к дополнительным данным ядра и проверка полных прав по чужому ID остаются отдельной серверной работой. SSH из сессии настройки недоступен.

## Ограничения

Кроме явно разрешённых почт учётных записей и преподавателей не предоставлять персональные данные, ответы, оценки, контакты, рабочие файлы, журналы с содержимым запросов, секреты и дампы. Реальные ID являются внутренними идентификаторами, а не полностью анонимными данными; использовать их только в защищённой среде. Справочник не меняет владельцев кабинетов и роли, не выполняет вход от имени другого пользователя и не обходит штатную авторизацию.

## Новые записи и более 200 кабинетов

Справочник читает БД при каждом запросе, не содержит зашитого списка аккаунтов. Новые пользователи и явные связи преподавателей появляются при следующем чтении. Обходить страницы по next_after до null; limit ограничивает одну страницу, а не общее число записей. Число аккаунтов здесь не подсчитано. Новые типы маршрутов, добавленные в ядре, требуют синхронизации метаданных ROUTES: список маршрутов в этом первом обработчике является проверенным снимком кода, не автоматическим индексом будущих страниц. Почты, зашитые в исходниках старых правил, не являются автоматически почтами действующих аккаунтов; не смешивать эти источники.
