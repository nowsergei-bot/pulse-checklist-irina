После успешного push в рабочую ветку обновление начинает проверки в течение примерно 30 секунд; публикация занимает ещё несколько минут. Исполнитель работает на Mac владельца: если Mac выключен или спит, обновление продолжится, когда он станет доступен.

## Первый запуск в Claude Code или среде с Git

Прочитай AGENTS.md, README.md и isolation-manifest.json. Проверь авторизацию собственного аккаунта Ирины. Если установлен GitHub CLI:

```sh
gh auth status
# При отсутствии авторизации Ирина проходит вход в свой аккаунт:
gh auth login --web --git-protocol https
```

Затем:

```sh
git clone --branch codex/checklist-irina https://github.com/nowsergei-bot/pulse-checklist-irina.git
cd pulse-checklist-irina
npm ci --prefix frontend
npm run dev --prefix frontend
```

Открыть http://127.0.0.1:5173. Это отдельная мастерская исходников; стартовый отчёт использует демонстрационные ответы. Рабочие ответы и БД не подключены. Если проект уже открыт, не клонируй второй раз: проверь origin и ветку, затем получи актуальные изменения без потери местных правок. Если среда Claude не умеет выполнять Git и отправлять коммиты, используй Claude Code или другую среду с авторизованным Git.

## Граница правок

Работай только с существующими файлами из `editable`: форма, отчёт, аналитика, PDF, карточки, расчёты и обработчики чек-листа. `context` — общие зависимости, их не меняй. Не меняй манифест, защитные скрипты, CI, общую навигацию, авторизацию, другие разделы и production-конфигурацию. Новые файлы, зависимости и SQL-миграции требуют отдельного изменения границы владельцем и автоматически не публикуются.

Сохраняй исходные ответы, данные и правила доступа. Не пересоздавай БД, не запускай миграции и сиды, не меняй домен. При конфликте не применяй force-push и не затирай чужие изменения; сообщи владельцу, какой файл конфликтует. Не пытайся самостоятельно вызвать облачный деплой.

## Публикация после работы

Выполни:

```sh
npm run build --prefix frontend
npm test --prefix frontend
npm test --prefix backend/functions
python3 scripts/check_scope.py
git status --short
```

Посмотри diff, добавь только конкретные изменённые файлы чек-листа, затем:

```sh
git add <конкретные разрешённые файлы>
git commit -m "Checklist: краткое описание изменения"
git push origin HEAD:codex/checklist-irina
```

Не создавай PR для публикации и не сливай изменения в main. Успешный push — запрос на автоматическое обновление живого чек-листа. Рабочие изменения, оставленные только в редакторе без commit и push, не публикуются. Делай push после завершённой и проверенной правки: каждый push этой ветки может попасть на живой сайт.

Сначала доверенный процесс сверит текущий живой релиз, проверит отсутствие конфликтов и выполнит сборку/тесты. Затем он отправит отдельный коммит в основной GitLab Пульса, проверит удалённый SHA и только после этого опубликует релиз. Остальные файлы берутся из текущей живой версии и остаются прежними. При конфликте или ошибке обновление остановится; не обещай Ирине, что сайт уже обновлён, только по факту push. Сообщи SHA отправленного коммита и что публикация ожидается; подтверждение публикации приходит владельцу от процесса обновления.

Если push вернул Permission denied / 403, сначала проверить, приняла ли Ирина приглашение и совпадает ли авторизованный аккаунт с приглашённым. Markdown не заменяет эти технические права. Предоставь владельцу GitHub-логин Ирины для назначения доступа.

## Синхронизация с живым Пульсом — 8 октября 2026

Ветка обновлена по подтверждённому текущему составу: сервер 86a9229 и интерфейс f9d067b, включающий изменения 528bc83 и 840440e. История всего Пульса сюда не переносится, поэтому исходные SHA могут отсутствовать среди коммитов этой отдельной мастерской. Экран сводки и настройки взяты из опубликованной версии. Сообщение «Сохранение связей ещё не включено в этом контуре» возвращает сервер, если таблица связей ещё не подключена; миграции мастерская не выполняет.

Один процесс владельца публикует правки этой ветки и синхронизирует сюда последующие подтверждённые опубликованные обновления чек-листа. Проверка опубликованного состава — каждые пять минут. Неопубликованные правки других чатов не копируются. При пересечении правок одного файла или несоответствии кода живому сайту процесс останавливается и сообщает владельцу; ни одна версия не заменяется автоматически.

Перед началом работы Claude должен выполнить `git pull --ff-only origin codex/checklist-irina`. Перед push снова получить обновления; при расхождении истории применить обычный rebase с разбором конфликтов. Не использовать force-push и не заменять папки целиком. Если есть незакоммиченные правки, сначала сохранить их локально и затем совместить с обновлениями. В обычной работе отдельно просить синхронизацию не требуется. Сервис работает, пока доступен Mac владельца.
