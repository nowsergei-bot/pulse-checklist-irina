# Рабочий Пульс: актуальная публикация

## Действующий порядок владельца от 16 октября 2026

Рабочее назначение правок Ирины — реальный новый Пульс: https://pulse.primakov-school.ru. API: https://pulse.primakov-school.ru/api; apiBase: https://pulse.primakov-school.ru (без /api). Отдельный monitoring-test и приватный предпросмотр не использовать как рабочее назначение. Этот порядок заменяет прежние указания о тестовом кабинете и отдельном разрешении на каждый обычный рабочий выпуск.

Рабочие ветки: `irina/checklist` для существующего чек-листа и `irina/english-monitoring` для `modules/monitoring/**`. Получить свежую соответствующую ветку, выполнить проверки и отправить изменения без force-push. Единственный издатель в закрытом GitHub совмещает правки с актуальным рабочим Пульсом, проверяет сборку и тесты на временной PostgreSQL, затем публикует в рабочий Пульс. Отдельный тестовый сайт для этого не нужен. Автопроверка новых правок запланирована каждые 15 минут; GitHub может запускать её с задержкой. Старые кнопки `monitoring-test-request` и `monitoring-live-request` не использовать.

Повторное согласование Сергея для обычных правок в действующих границах не требуется. Push не означает немедленную публикацию. Ошибка тестов, конфликт с параллельной правкой или незавершённый выпуск останавливают установку. После выпуска проверять нужный раздел на рабочем домене; установленный полный SHA — `/release.json`. При необходимости владелец может сразу запустить `Pulse checklist live` в закрытом репозитории.

Сохраняются ограничения исходников: общий код авторизации, ядро, инфраструктура, CI, защитные скрипты, корневые зависимости и чужие разделы не редактируются. Не помещать секреты, реальные ответы и выгрузки в публичный GitHub. Применённые миграции неизменяемы. Рабочий перенос сейчас охватывает существующие файлы чек-листа и `modules/monitoring/**`; новые `modules/irina/*` требуют подключения к рабочему приложению, автоматическая публикация их останавливает и не уводит в тестовый кабинет.

Старый Пульс Yandex не использовать. Пароли сервера и базы, приватные ключи и токены закрытого GitHub Ирине и Claude не нужны.

# Мастерская чек-листа Пульса

Отдельный публичный репозиторий для Ирины Костюкович. Рабочая ветка: `codex/checklist-irina`. Репозиторий содержит раздел чек-листа и необходимые общие зависимости, без страниц других разделов, инфраструктуры Пульса, секретов и выгрузок ответов.

## Локальный просмотр

Node.js 22+, Python 3, Git.

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Это отчёт чек-листа с синтетическим педагогом и демонстрационным ответом. Полный рабочий кабинет и сервер не запускаются: это мастерская исходников и локальный просмотр отчёта. Производственные API не настроены; политика браузера запрещает внешние соединения. Для остальных экранов нужно отдельно добавить демонстрационные сценарии. Прежние исходные справочники в коде сохранены; реальные ответы из БД не копировались.

## Граница правок

`isolation-manifest.json` содержит точный список `editable` (189 файлов чек-листа) и `context` (общие зависимости только для чтения). Backend включает обработчики, расчёты и миграции чек-листа; общие backend-зависимости даны как контекст. Не менять общие зависимости, манифест и механизм переноса. Новые файлы требуют отдельного согласования границы владельцем.

```sh
npm run build --prefix frontend
npm test --prefix frontend
npm test --prefix backend/functions
python3 scripts/check_scope.py
```

46 выбранных тестов, сборка TypeScript и Vite. Остальные интеграционные тесты исходного Пульса могут требовать его отсутствующие страницы, сервер или БД; полный тестовый набор здесь не заявлен.

## Возврат изменений в Пульс

Не сливать историю этого репозитория в Пульс и не копировать целиком папки. Владелец использует доверенную версию `scripts/export_patch.py` и исходный SHA `main` из первой поставки:

```sh
python3 scripts/export_patch.py 3d507a4669b79ad7330945f1723fa353172dcd56 /path/to/survey-app > checklist.patch
```

Скрипт ничего не пишет в Пульс. Он допускает только исходно выделенные файлы чек-листа и проверяет SHA-256 каждого изменённого файла в текущем Пульсе. При параллельных правках останавливается, нужен ручной перенос. После проверки патча владелец создаёт отдельную ветку Пульса, проверяет патч через `git apply --check`, переносит изменения, выполняет проверки и отправляет в GitLab `origin`. После push в codex/checklist-irina локальный процесс автоматически проверяет и публикует изменения чек-листа в существующий живой Пульс. PR и одобрение не нужны. Проверка ветки — каждые 30 секунд, пока Mac владельца доступен; сборка и публикация занимают несколько минут. Он строит релиз от точного коммита действующего API, сверяет его со статикой и серверным пакетом, переносит только файлы чек-листа, отправляет релиз в GitLab и проверяет удалённый SHA перед публикацией. При конфликте, ошибках сборки или миграции БД останавливается и сообщает владельцу. Рабочая ветка Ирины является источником автоматической публикации. БД и домен не переключаются.
