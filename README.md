# Мастерская чек-листа Пульса

Отдельный публичный репозиторий для Ирины Костюкович. Рабочая ветка: `codex/checklist-irina`. Репозиторий содержит раздел чек-листа и необходимые общие зависимости, без страниц других разделов, инфраструктуры Пульса, секретов и выгрузок ответов.

## Локальный просмотр

Node.js 22+, Python 3, Git.

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Это отчёт чек-листа с синтетическим педагогом и демонстрационным ответом. Полный рабочий кабинет и сервер не запускаются: это мастерская исходников и локальный просмотр отчёта. Производственные API не настроены; политика браузера запрещает внешние соединения. Для остальных экранов нужно отдельно добавить демонстрационные сценарии. Прежние исходные справочники в коде сохранены; реальные ответы из БД не копировались.

## Граница правок

`isolation-manifest.json` содержит точный список `editable` (183 файла чек-листа) и `context` (общие зависимости только для чтения). Backend включает обработчики, расчёты и миграции чек-листа; общие backend-зависимости даны как контекст. Не менять общие зависимости, манифест и механизм переноса. Новые файлы требуют отдельного согласования границы владельцем.

```sh
npm run build --prefix frontend
npm test --prefix frontend
npm test --prefix backend/functions
python3 scripts/check_scope.py
```

46 выбранных тестов, сборка TypeScript и Vite. Остальные интеграционные тесты исходного Пульса могут требовать его отсутствующие страницы, сервер или БД; полный тестовый набор здесь не заявлен.

## Возврат изменений в Пульс

Не сливать историю этого репозитория в Пульс и не копировать целиком папки. Владелец использует доверенную версию `scripts/export_patch.py` и исходный SHA `main` из первой поставки:

```sh
python3 scripts/export_patch.py 221ad16ed1c263426ec7940fad45bf0f2a6d4d09 /path/to/survey-app > checklist.patch
```

Скрипт ничего не пишет в Пульс. Он допускает только исходно выделенные файлы чек-листа и проверяет SHA-256 каждого изменённого файла в текущем Пульсе. При параллельных правках останавливается, нужен ручной перенос. После проверки патча владелец создаёт отдельную ветку Пульса, проверяет патч через `git apply --check`, переносит изменения, выполняет проверки и отправляет в GitLab `origin`. Изменения с GitHub никогда не публикуются в рабочий Пульс автоматически. Деплой и переключение БД требуют отдельного разрешения.

## Доступ

Публичное чтение доступно без приглашения. Запись в ветку требует доступа GitHub collaborator (Write) и принятого приглашения. Claude работает через GitHub-аккаунт Ирины, подключённый в её среде. Пароли и токены не передаются в Markdown. См. `CLAUDE.md`.
