# Среда «Мониторинг результатов»

Стек: React 18, TypeScript, Vite; сервер Node.js, PostgreSQL. Код модуля находится в `modules/monitoring/`, страницы — в `pages/`, обработчики — в `server/`, SQL — в `migrations/`. `legacy/` содержит справочную копию старого английского раздела и не участвует в сборке.

Маршруты кабинета: `/cabinet/monitoring/*`. Страница `pages/index.tsx` управляет всеми вложенными страницами; добавляйте свою маршрутизацию внутри модуля. Серверные запросы идут на `/api/monitoring/*`; `server/routes.cjs` получает `path`, `method`, `query`, `body`, `user`, `db`, `release`. Добавление маршрута не требует изменения ядра.

`db.query(sql, params)` использует отдельное подключение ограниченной роли. Запись разрешена только в `monitoring`. Общие данные доступны через представления `pulse_read`; дата рождения и пол учеников не передаются. В SQL всегда используйте параметры. Не записывайте ФИО, почты, идентификаторы аккаунтов, содержимое файлов и строки подключения в код, логи, ошибки и публичные задачи.

Пользователя устанавливает шлюз Пульса после проверки штатной сессии и CSRF. Модуль выполняется в отдельном контейнере без подключения администратора БД, секретов других проектов и Docker socket. `user` содержит идентификатор, имя, роли Пульса и роли модуля. Доступ разрешён только пользователям `monitoring.user_roles`; родители, ученики и неактивные аккаунты не проходят шлюз. Не доверяйте user из тела клиентского запроса. Первый администратор назначается владельцем в закрытом контуре, идентификатор не публикуется в мастерской.

Миграции именуйте `NNN_название.sql` (латиница). Исполнитель применяет их по порядку, каждую в транзакции, под ограниченной ролью, с блокировкой параллельного запуска. `monitoring.schema_migrations` хранит имя и SHA256. Уже применённые файлы менять нельзя: добавляйте следующий. Ошибка или изменение контрольной суммы останавливает публикацию. Не включайте BEGIN/COMMIT в SQL-файлы: транзакцией управляет исполнитель. Сначала тестовая среда, затем проверенный рабочий релиз.

Существующие библиотеки: Excel — `xlsx`, `exceljs`; PDF — `jspdf`, `pdf-lib`, `html2canvas`, `pdfjs-dist`; графики — `recharts`, `@xyflow/react`. Новые зависимости требуют обновления package.json и lock-файла в закрытом ядре, проверки и сборки. Не устанавливайте пакеты на сервере из обработчика.

Тестовый адрес: https://monitoring-test.primakov-school.ru/auth. Вход штатный; тестовая БД является отдельной копией рабочей. Автопубликацию и откат выполняет доверенный закрытый исполнитель. Версию мастерской можно проверить на `/api/monitoring/version` после входа. Рабочая публикация идёт через единственный издатель Пульса после проверок и сверки SHA. Откат кода не отменяет миграции: изменения схемы делайте обратно совместимыми, откат БД — только из проверенной копии отдельным действием владельца.

Файлы хранятся в префиксе `monitoring/` отдельного закрытого S3-бакета модуля; рабочая и тестовая среда используют разные бакеты и ключи. Серверный обработчик получает `files.put({filename, mediaType, content: Buffer}, user)` и `files.get(uuid, user)`. Метаданные находятся в `monitoring.files`; выдача разрешена владельцу файла и `data_admin`. Размер одного файла — до 3 МиБ. Реальные файлы, имена пользователей и метаданные не публикуются в мастерской. Для нового маршрута загрузки разбирайте тело запроса в обработчике; `files.get` возвращает Buffer, который можно выдать как base64 внутри JSON. Бакеты и файлы не удаляются при обновлении кода. Ключ модуля не имеет доступа к файлам остальных разделов Пульса.
